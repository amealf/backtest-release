# 项目约束

## 已确认约束

- 超出用户明确要求或已经同意方案的修改，必须在实施前取得许可。迁移任务开始时，agent 要询问缺少的原品种、目标品种、数据／样本、成本、gap 与执行信息，然后生成经审阅的迁移方案文件。展示列名从方案读取原品种与目标品种名称；候选过滤规则在获得单独同意前保持待定。
- 迁移完成后的交付包含五项：原品种总入口、原品种逐笔分析、合并跨品种排序、目标品种逐笔分析与迁移报告。原品种入口和跨品种入口采用新标签页双向互链。
- 迁移 HTML 采用增量发布。新的合并运行通过 `incremental_parent_run` 声明已完成父运行；固定构建器复用父运行中每个未变化的目标品种逐笔区块，只为新增候选生成新区块。小型排序索引、目录与汇总可以更新，但不能重新生成未变化候选的逐笔区块。
- 存在兼容当前快照时，K200 最终累计发布采用增量方式：复用确定性命名且未变化的逐笔区块，只生成缺失坐标区块，同时更新累计排名、目录、汇总与清单。复用过程不得改变历史逐笔证据或结果指标。
- 实现与核验保持精简。采用满足已确认契约的最小代码改动；只有具体且严重的风险才增加防御分支。除非语义、数据、结果发生变化，或已经观察到故障，否则不运行大范围回归、重复哈希审计与浏览器矩阵。工作存在可视结果且环境允许时，提供一张有代表性的截图，并判断是否存在重叠、乱码、不对称或明显布局错误；本地 Chrome `file:///` 页面可使用 Computer Use 打开。
- V4.4 位于 `D:\Code\backtest-release\Backtest V4.4`；V4.3 保持为不可变历史证据。
- V4.4 结果字节物理存放于 `F:\Backtest\Backtest V4.4\results`。兼容逻辑路径 `D:\Code\backtest-release\Backtest V4.4\results` 是指向该 F 盘根目录的 Windows 目录联接。后续结果 writer 必须保留此映射；源码、计划与项目管理继续位于 D 盘。
- 已完成评价统一保存到 `results\evaluation_packages\<instrument_id>\<evaluation_start>__<evaluation_end>`，时间目录精确到秒。目录名不写训练、测试、迁移、留出或描述性角色。
- 每个结果包记录准确品种、区间、时区、bar 周期、参数汇总、按候选集生成的浏览器精简数据、不可变逐笔记录、逐笔入口、来源与实验说明。历史兼容结果包可以硬链接不可变记录，并让逐笔入口跳转到保留且字节不变的历史页面。
- 每份回测计划绑定一个已就绪品种配置和一个精确评价区间。数据、准备清单、成本、gap、低活跃、bar 颗粒度和实验模式要求齐全后，可以单独运行任意品种和时间区间。
- 通用比较入口通过 `comparison_plan.json` 选择已完成结果包，按精确 `combo_id` 连接，不根据目录名判断证据角色。坐标缺失或重复时，比较不能标记为完成。
- 当前 K200 稳定总入口／逐笔入口，以及保留的 350 组比较页和逐笔页保持字节不变。日期结果包页面只有在逐行数值完全一致、可见正文一致、首行数据一致、渲染行数一致且浏览器无错误后，才可以成为稳定入口目标。
- `rolling_tr_sum` 仍是唯一 baseline 方法。`all_window` 为默认策略；`exclude_marked` 可选，并使用因果 `baseline_available_from` 时间。
- W 候选使用 1 到 W 的全部可用前缀，不要求累积满 W，也不设置最小窗口比例；早期前缀形成的最大值可以继续控制本次持仓。
- W 候选精确定义为 `w_open_to_end_low_drop = open[start] - low[end]`，不表示窗口内部 high 到后续 low 的最大有序下跌。原始审计字段名为兼容性保留。
- pending entry 属于 `fill_first_real_open` 保留信号：在 120 根连续候选 bar 边界内按第一根真实成交 bar 的 open 开仓，不要求 trigger 再穿越，也不因更高 high 或结构反转取消。
- 非真实 bar 上的回撤或速度信号仍进入 pending，并在样本内下一根真实成交 bar 的 open 平仓。
- 每个后续 campaign 都要绑定品种成本参考。名义价值等于冻结参考价乘以 point value；手续费、滑点与必要汇率转换共同决定该阶段的往返 bps。原始运算保留 `entry_slippage=0`、原始成交与原始收益。现有 K200 行保留历史成本参考，不进行重算。
- 策略语义、品种设置与 campaign 意图属于三项独立权威。新品种只有在用户确认成本模型和 gap policy 以后才能执行。
- 四种正式模式为 `transfer_exact`、`target_local_refinement`、`continuation_search` 和 `fresh_search`。完整迁移要求 freeze 与 plan 坐标集完全相同；局部细化需要相同目标品种的已完成迁移父实验与机器验证的有限邻域；续探需要同品种、同谱系的已完成父阶段；全新搜索不导入源候选或父阶段，并绑定当前探索指南与合法搜索空间。
- K200 的权威执行颗粒度为 15 秒。每个迁移目标必须同样使用 15 秒，并由策略协议、源／目标配置、数据准备清单与实际数据网格一致证明。任一不一致都要停止并报告用户。
- schema-v5+ 的 `profile_optional` 遇到没有 scenario set 的品种配置时表示无情景；K200 事件回退只允许明确 legacy 执行。
- gap 与低活跃 policy 属于受支持、绑定哈希的可执行身份。profile 声明必须与数据准备清单中的 policy／配置／实现身份一致；自由文本 `ready` 标签不足以执行。
- 后续开仓资格要求 baseline、drop 与 threshold 都是有限正值，并保留 `drop >= threshold` 的正值边界相等。历史原始与衍生结果文件保持不变。
- 累计排名以已接受的 V4.4 K200 大版本谱系作为分界。V4.4 内的小修正继续与现有行进入同一累计页面。引擎、数据准备、策略、结果语义、计划与产物哈希继续作为阶段来源和完整性证据，不再建立新的排名分区。升级到 V4.5 时建立新的 K200 排名谱系。其他品种保留独立排名，只在跨品种比较中并列展示。
- 每个参数探索 agent 都必须阅读并遵守 `project_management\05_domains\research\PARAMETER_EXPLORATION_GUIDE.en.md`。改善由模型结合多项指标解释，不给任何指标设置长期高权重，也不使用固定综合分数。
- 参数搜索分辨率必须匹配参数尺度。E、BH、S 使用相对乘法网格；按个位数绝对步长持续加密，视为过拟合。跳跃搜索阶段覆盖互不相邻且采样不足的区域；网格阶段只细化已有闭合证据支持的锚点。
- 探索采用 AI 主导的循环：多轮跳跃搜索、围绕互不相邻优秀锚点的有限单参数网格、再次跳跃搜索。单轮可以只属于一个阶段。每个网格固定其余字段，只测试一个参数；点数不设固定上限，但运算前必须冻结有限边界、步长安排、锚点和预计坐标数。跳跃与网格证据在完整循环中分开解释和报告。
- 用户可以在循环之间修正目标、锚点、范围或方向。用户暂时不在线时，自主工作不得超出明确授权的时长、品种、方法、数据和资源边界。
- Mini KOSPI 200 最小变动单位资料继续只作来源背景。KRX 合约乘数是当前成本输入。
- 交付必须使用既有历史主入口／逐笔模板和绑定的本地 Plotly。
- 每次实验都需要经审阅计划、隔离输出、不可变原始闭合和明确证据边界。中间轮只保留原始结果和小型汇总。整组探索结束后生成一次累计总入口与共享逐笔 HTML；只有用户明确要求时才中途发布。
- 一个执行者或多个执行者均可完成分析、回测运算与 HTML 交付。交付不得从未闭合的原始结果开始工作。
- Round N 原始结果不可变闭合后，其 HTML 交付与证据分析可以并行。Round N+1 的规划、验证与运算只能在当前 `SOURCE_FINAL` 已闭合、计划／源码身份及 completed+active+pending 精确反连接通过、输出根目录与锁相互独立、最新内存／资源门槛计入正在运行的交付进程，并且累计 HTML／union writer 恰好只有一个时重叠进行。
- 整组探索结束后，最终累计总入口与共享逐笔入口只需完成一次 `DELIVERY_FINAL`。该次发布发现影响结果的源码不一致时，暂停后续运算，直到新源码身份闭合。
- 验证按风险分级。版本、引擎、成交、收益／成本、数据、schema、执行契约与结果语义变化需要完整回归测试；前端行为变化需要针对性交互检查；纯文案／样式／布局变化只需重新生成 HTML、简单功能检查及桌面／手机截图，除非同时影响行为或数据，否则无需完整测试。
- 用户要求 ZIP 时，包含当前版本代码、项目管理、分析报告、哈希绑定的 15 秒 OHLC，以及每个已完成 V4.4 阶段的逐笔交易 CSV。对运算结果的唯一例外是 `batches/**/trades.csv` 与每个已完成阶段的衍生 `analysis/stage_trades.csv`；它们复制到 `trade_records/`，并由哈希绑定的逐笔记录清单说明。其他结果载荷继续排除。
- 正式源码发布 ZIP 必须保留项目相对目录结构，并包含包内测试所需的全部仓库模块、模板、计划定义、运行输入、依赖声明与本地结果 fixture。压缩包必须提供一条包根目录测试命令，并在独立解压副本中通过该命令。紧凑 UI 审阅 ZIP 只有在明确标注为不可执行时，才可省略无关的源码／测试依赖。
- 每轮参数探索结束时，都要在独立交付文件夹中用 `next_round_parameters.csv` 保存完整展开且唯一的下一轮坐标。CSV 通过 completed+active+pending 精确反连接后，才能绑定为经审阅的执行计划。
- 通用迁移路径用于完整目标数据以前，必须用小型 15 秒端到端 fixture 证明 freeze／plan 精确身份、目标成本、目标空情景、目标独立谱系、目标名称展示、freeze 变化导致身份失效、拒绝目标调参与颗粒度门禁。

## 当前探索边界

活动修复后 K200 结果继续使用 campaign `v4_4_positive_entry_signal_repair_20260805`，当前累计快照保持不可变。后续 V4.4 小修正使用排名谱系 `k200m_v4_4_positive_entry_future_lineage`；即使实现或数据准备哈希不同，也会与现有 V4.4 结果共同排序。SImain、NQ 或其他品种使用自己的谱系。每个中间轮次需要不可变原始闭合、逐行理由 CSV、精确反连接及经审阅的哈希绑定计划；累计 HTML 在整组结束后统一发布一次。样本内领先坐标不等于参数被接受。
