# 项目约束

## 用途

记录跨项目长期有效的约束。领域专属规则保存在已确认的可选模块中，不能假定该领域存在。

## 已确认约束

| 约束 | 理由 | 证据或负责人 | 状态 |
| --- | --- | --- | --- |
| 初始化管理目录时保留用户已有文件。 | 初始化过程需要可审阅、可恢复。 | 项目管理协议 | 当前 |
| 保持英文执行文档与中文审阅镜像一致。 | Agent 需要单一执行来源，审阅者需要易读镜像。 | 项目管理协议 | 当前 |

| pending entry 在既有等待与连续性边界内，以第一根真实成交 bar 的 open 成交；不增加价格重触发、创新高取消或结构反转取消。 | 保留已确认的开仓行为。 | 用户确认 | 当前 |

| 使用既定总入口／逐笔模板；替换指定项目或扩大需求前必须取得用户确认。 | 保留既定审阅流程与沟通边界。 | 用户纠正 | 当前 |

| 任务需要使用或查看场景时，打开跨版本共享场景管理 HTML；不能从版本专属结果页面推断场景定义。 | 让各回测版本使用同一套可编辑场景库。 | 用户指令 | 当前 |

## 质量与完整性

- 在相关内容存在时，保持当前路径、配置、输入、输出与有效边界可追溯。
- 所有策略、结果、组合、审计与 fingerprint 身份都必须使用 V4.3 版本。
- 当前两种采样策略都不会排除全部 synthetic bar。real-only 或排除 synthetic 的 baseline 需要单独批准的研究契约。
- 实现、文档或验证工作本身不授权启动回测。
- 本长期约束文件不记录会频繁变化的实验数量与排名。

只有用户确认、修改或退役长期约束时更新。相关变化形成长期选择时，在 `04_decisions\DECISIONS.en.md` 中记录理由。
