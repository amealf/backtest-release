# 变更理由

## 用途

解释后续工作可能需要复核的重要行为变化。每项记录保存修改原因、原有表现、更新后表现与证据影响，作为简明决策登记和工作进展日志的补充。

## 何时新增记录

修复或其他重要变化改变可观察行为、默认值、有效边界、可复现性、证据解释或重要用户流程时，新增记录。长期选择写入 `DECISIONS.en.md`，已完成工作摘要写入 `WORK_PROGRESS.en.md`。

普通状态更新与轻微呈现调整通常不需要记录；它们实际影响审阅或使用时可以记录。

## 2026-08-02 — 版本中立的场景库

**修改原因：**场景查看器曾被表现为版本专属入口，造成场景查询与编辑分散。

**原有表现：**版本结果页可以展示场景要求；指定市场选定器能够建立行情区间，但不会持久保存可复用场景，也不能管理已保存定义。

**更新后表现：**指定选定器的共享副本可把一段或多段行情自动保存为连续的 `情景N`，编号同时统计回收站，因此不会复用。当前场景在图表上方以两行按钮展示，点击即可载入；删除场景仍可恢复。标题／主题首行已经移除，上传入口移到下方操作行；显示默认使用 15 秒，并支持 1／5／15／30／60／120 分钟。

**证据影响：**后续任务使用同一个稳定 HTML，并点击已保存场景按钮完成选择，再把已审阅、不可变的场景定义绑定到版本专属计划。原始选定器字节与历史结果快照保持不变。

**有效边界：**浏览器本地存储通过固定 HTML 路径在同一浏览器配置中共享；它本身不授权启动回测，也不替代计划／manifest 身份门禁。

## 2026-08-02 — 可选择的 baseline 采样

**修改原因：**V4.3 需要同时保留默认的全窗口 baseline 与可选的排除标记 baseline。原准备层表述错误地暗示某一种选择普遍适用。

**原有表现：**引擎固定使用全部有限 TR15 原子；准备层发布的字段名称像是已经替回测作出 marker eligibility 决定；下游身份与排名没有采样策略轴。

**更新后表现：**准备层发布中性标记与 `eligible_if_excluding_marked`。计划为每个阶段选择一种策略。`all_window` 保持默认；`exclude_marked` 在同一连续段内向前补足更早的未标记有限原子。策略专属身份与排名贯穿计算和交付。

**证据影响：**准备 schema／身份、运行／来源 manifest、combo／fingerprint／stage／completion／analysis／catalog 身份与当前 UI 控件发生变化。当前 V4.3 结果数仍为零，因此没有迁移结果。

**有效边界：**两种策略都使用 `rolling_tr_sum`；两者都不会移除全部 synthetic bar。

## 2026-08-02 — 审计与输入完整性修正

**修改原因：**`baseline_pending_atom_count` 在存在真实 pending 低活跃原子时仍被固定为零；引擎层对重复 datetime 缺少失败关闭。

**原有表现：**pending 数量来自全 false 数组；重复时间戳在排序后继续存在，可能扰乱连续性。

**更新后表现：**pending 数量按物理 baseline 跨度内真实低活跃 pending 状态统计。来源 datetime 重复会在执行前报错。当前 UI 源移除 `tr_average`，兼容排名增加 `>=10`。

**证据影响：**审计字段与输入验证发生变化；pending 数量修复不改变交易规则。格式错误的重复输入现在会被拒绝。

**有效边界：**没有发现 `_rank()` 重复赋值，因此未针对该报告进行无证据清理。

## 2026-08-01 — 真实成交平仓执行

**修改原因：**rebound 与 speed 条件可能在 synthetic／无成交 bar 上成立，但这些 bar 无法提供市场成交。

**原有表现：**引擎使用 synthetic bar 派生的 close 或计算阈值立即平仓。

**更新后表现：**第一次触发原因、时间、理论价格与证据冻结为 `pending_exit`；持仓继续存在，在下一根真实成交 bar open 成交，之后才重置为空仓。

**证据影响：**必须使用新的 pending-exit 审计字段、V4.3 身份、引擎测试、分析器检查与逐笔来源验证。V4.2 结果不能作为 V4.3 结果复用。

**有效边界：**适用于 rebound 与 speed 信号平仓。segment-end 仍保留独立的强制结束规则。

## 2026-08-01 — 可移动的活跃运行环境

**修改原因：**机器绝对路径会阻止干净迁移与复现。

**原有表现：**活跃默认值从特定 D:/F: 位置打开数据与模板资产。

**更新后表现：**活跃默认值从 `runtime_inputs` 下仓库相对文件解析；历史绝对路径只保留为来源记录。

**证据影响：**运行与来源 manifest 绑定本地路径和哈希；移动文件夹不再需要修改代码。

**有效边界：**适用于活跃 V4.3 runtime。来源 JSON 可以保留历史路径，但不会成为依赖。

## 记录格式

```markdown
## YYYY-MM-DD — 简短变更标题

**修改原因：**为什么需要这项变化。

**原有表现：**变化发生前的行为。

**更新后表现：**当前行为。

**证据影响：**哪些产物、测试、记录或解释受到影响。

**有效边界：**新解释适用于哪里，哪些内容保持不变或待确认。
```

## 维护规则

新记录放在旧记录上方。链接证据，不复制大型输出。同一变化影响当前行为、代码架构或长期选择时，同时更新 `CURRENT_VERSION.en.md`、`CODE_ARCHITECTURE.en.md` 或 `DECISIONS.en.md`。
